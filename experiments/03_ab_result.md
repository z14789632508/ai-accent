# 实验 03 结果：禁词把八股挤到了结构层

跑于 2026-11-23，DeepSeek `deepseek-flash`，`thinking=disabled`，`temperature=1.0`，`max_tokens=400`。
A/B 各 **300 条**，**同一个 prompt 池**（真实用户消息里抽的 300 句，长度 4–80 字），参数完全一致，唯一差别是 B 组的系统提示多了一段禁用词表。

## 两组设置

```
A: 你是一个中文聊天伙伴。用自然的中文和对方说话。

B: 同上 +
   严禁使用以下词语：总的来说、总而言之、综上所述、首先、其次、再次、最后、
   希望对你有帮助、希望对你有所帮助、值得一提的是、需要注意的是、值得注意的是、
   另一方面、此外、换句话说、让我们一起、总结一下。
```

## 结果

| | A（无禁令） | B（词表禁令） | 变化 |
|---|---|---|---|
| 禁用词命中 / 千字 | 0.36（9 次） | 0.20（4 次） | **↓ 44%** |
| 句末标点率 | 90.4%（330/365） | **99.1%（313/316）** | ↑，z=4.90，p<1e-5 |
| 单段回复占比 | 90.0% | **97.0%** | ↑ |
| 连发条数熵 | 0.676 | **0.235** | ↓，bootstrap 95% CI [−0.66, −0.22] |
| 段内长度 CV | 0.436 | 0.394 | ↓ |
| 单段长度中位数 | 64 字 | 54 字 | ↓ |

段数分布：

```
A: {1段:270, 2段:12, 3段:10, 4段:3, 5段:2, 6段:2, 7段:1}
B: {1段:291, 2段:3, 3段:5, 4段:1}
```

## 判读：① 水床成立

按 `01_wordlist_effect.md` 里事先写死的判读表：

> ① B 组词级命中率显著下降，**且**结构指标更整齐 → **水床成立**。

- 词级：命中率降到一半（9 → 4 次）。
- 结构：**四个方向全部往"更整齐"走**——句末标点 +8.7 个点、单段占比 +7 个点、条数熵降到 1/3、段内 CV 下降、段长更短更齐。

也就是说：词表确实干掉了一半的八股词，代价是**输出的形状变得更像一个模板**。它不是在教模型"像人说话"，是在教它"别踩这几个词，然后把话收得整齐一点"。

## 两个值得单独说的发现

**1. 负向约束漏了。** B 组自己列了 17 个禁用词，仍然出现了 `最后`×3、`另一方面`×1。这不是模型不听话，是"不要在生成空间里避开某些点"这件事本身没法严格执行——它只能在附近重新采样，偶尔就落回原处。这正是 `01` 里写的机制①。

**2. 两组都不像人，只是不像的方向不同。** 真人句末标点率是 8.7%，A 组 90.4%、B 组 99.1%。一个裸的"聊天伙伴"提示本来就离人很远——**词表让它在"已经不像人"的基础上，更像一份文档。**

这也说明为什么单看 A 组也会得出错误结论：如果不跟真人基线比，只看 A 组，会觉得"90% 有标点，挺正常"。**没有基线，八股是不可见的。**

## 这张表不能证明的

- **不能证明幅度。** 300 vs 300 只能说明方向，说明不了"词表会让八股恶化多少"。要幅度得换更大的 prompt 池和更多格。
- **不能外推到生产人设。** 这里用的是裸提示，模型默认输出就是"一段话 + 句号"；线上大肥鱼的人设会把它掰成"三条短消息"，那是另一层形状（89% 恰好 3 段），两者的结构指标不能直接横向比。
- **词级命中绝对量太小**（9 vs 4 次），比率上的 44% 容易被单条样本撬动。方向可信，精度不可信。

## 复现

```bash
# 1) 准备 prompt 池：data/ab/prompts.jsonl，每行 {"p": "..."}
# 2) 跑（读本机 AstrBot 配置里的 deepseek key；共 600 次调用，约 92 秒）
python experiments/ab_wordlist.py --n 300 --workers 12
# 3) 体检
aiaccent audit data/ab/a.jsonl --register chat
aiaccent audit data/ab/b.jsonl --register chat
aiaccent diff data/ab/a.jsonl data/ab/b.jsonl
```

产物 `data/ab/{a,b}.jsonl`、`raw.json` 含原文，不进仓库（`.gitignore` 已排除 `data/`）。
