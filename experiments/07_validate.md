## 1. 设置

```bash
set AB_ASTRBOT_CONFIG=<AstrBot cmd_config.json>
python experiments/run_07.py --n 120 --workers 12
```

- 池：`data/ab/prompts.jsonl` 前 120 条（与 06 同一批，可横向比）
- 模型：deepseek-flash，temp 1.0，max_tokens 400，thinking disabled
- A / C / T 各 120 次调用（**360 次，58 秒**）；D 由 A 本地扰动（seed 7000+i）
- C 臂 = `user_style` 2 条 + 「短的是信息不是态度」；T 臂 = 再加 `model_tics` 2 条

**T 臂的完整指令**（5 行）：

```
- 这个用户习惯几乎不写句号（实测 end_punct_rate = 0.036）…句末很少用句号…
- 这个用户习惯长短差得很开（实测 chunk_len_cv = 1.955）…长短交错…
- 这个模型的毛病是对冲词密度偏高（模型默认如此）…别每条都补一句缓冲…
- 这个模型的毛病是每句结尾都问回去（模型默认如此）…允许一轮里不带问句…
- 短的是信息，不是态度：要削的是铺垫、解释、客套；关心、情绪、判断这些半句要留着…
```

口径说明（诚实起见）：
- 07 的留出集减到 4 项（`turn_share_3`、`turn_chunks_entropy`、`within_turn_cv_median`、`sentence_len_entropy`）。
  `hedge_chunk_share` **不能算留出**——T 臂的毛病指令本来就冲着 hedge 去，它在带内不算泛化，算直接命中。
- D 臂保留 40.86 的高位，说明"随便改改"不会自动变好；C（7.37）与 T（5.43）才是方向正确的改动。

## 3. 三条可直接读出来的差别（C vs T）

1. **对冲密度真的降下来了**：7.64 →（C）4.34 →（T）**2.89**，人类 1.25。
   06 里这味药没开时是 8.28 → 7.29 纹丝不动；这次直接砍掉一半多。**第二味药是有效的。**
2. **T 开始分条了**：`turn_chunks_median` C 是 1.0，T 是 **2.0**（人类带 1.4–3.0）。
   C 的改善全靠"每段截短"，T 才第一次碰到"一次说几条"这个维度。
3. **标点更靠近人**：C 的 0.026 几乎贴下边界（"几乎不写"被执行成"基本不写"），
   T 的 0.057 略高但离带更近。频率措辞比绝对措辞稳，但仍会过冲——说明"十句里最多一两句"
   这个锚点还不够硬，下一版要写成"多数句子不带标点，偶尔带"。

## 5. 已知限制

- 判官是被模仿者本人（同 06），存在"我知道该选哪个"的先验。
- 单条 dev 噪声大：`chunk_len_cv` 在单条上几乎没意义（一条消息的段内 CV），
  所以 P4 只是探索性，不应当作结论。
- 只测一个模型、一个温度、一个人。
