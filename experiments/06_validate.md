# 实验 06：验收实验 —— 改完到底有没有变好（预注册）

状态：**设计已定稿，未运行**（2026-11-28）
前置：01/03/04 证明了"禁词把八股推到了结构层"；05 证明了"字面承接率方向是反的"。
本实验要回答的是另一件事：**按 prescribe / adapt 给的指令改完之后，人是不是也觉得更好。**

写这份文档的目的不是描述计划，而是**先把判据钉死**。判据写在这里之后不许改；跑出来不达标就照实记负结果，不许换判据重跑。

---

## 0. 为什么必须做这个

现在的所有数字都在说"机器离人多远"，没有一个在说"改了之后离人近了多少"。
如果没有这一步，`audit → prescribe → adapt → 用户改 prompt` 就是一个新的优化环，只是把 `Human Score` 换成了 `dev / pct / verdict` —— 这跟被批评的禁词表是同一个病，换了个位置。

---

## 1. 三个独立的问题，别混着答

| 层 | 问题 | 我们现在的答案 |
|---|---|---|
| Judge | 谁来判 | **只能是自己盲测 + 真实聊天**，没有用户盘子（见 §4） |
| Target | 判什么 | **不问"像不像 AI"**，问"愿不愿意继续聊 / 读着顺不顺 / 有没有在迎合我 / 像不像同一个人"（见 §3） |
| Validation | 怎么防自证 | 四臂对照（含随机扰动臂）+ 留出指标簇 + 预注册判据（见 §2） |

最容易错的是 Target 那一层：**把可测的东西当成重要的东西**。所以本实验的成败判定里，人味那一条（P1）权重最高，指标只是辅助证据。

---

## 2. 四臂设计（防自证的核心）

同一批 prompt，四组输出：

| 臂 | 内容 | 作用 |
|---|---|---|
| **A 原样** | 只给基础系统提示 | 下限基准 |
| **B 禁词表** | 基础提示 + 62 字禁用词句（与实验 03/04 同一份） | 代表现有主流做法 |
| **C 适配** | 基础提示 + `adapt` 生成的 ≤3 条结构指令 | 本项目的主张 |
| **D 随机扰动** | 基础提示 + 对 A 的输出做随机结构扰动 | **关键对照** |

**D 臂怎么做**（必须照这个做，否则 D 就没有意义）：拿 A 的输出，按 `baselines/chat.json` 的分位表随机抽目标长度、随机决定要不要句末标点、随机把 1–2 段合并或拆开、随机删掉一句。目标是让 A 和 D 的**分布距离**与 A 和 C 的可比。

D 的意义：如果 **A→D 也能提高人的评价**，那说明 C 的改进只是"增加了随机性"，不是"结构适配"这套理论对。这种事在实验里经常发生，不设 D 就分不清。

**提示池**：120 条，来源与 03/04 的 chat 池相同（livingmemory 里 4–80 字的真实用户消息，seed 固定）。
**调用量**：120 × 3 = 360 次（A/B/C 各一次；**D 由 A 的输出在本地扰动生成，不调 API**），deepseek-flash，temp 1.0，thinking disabled。实测 55 秒、prompt 27,516 tok + completion 13,449 tok。

---

## 3. Target：判什么（四条，都别问"像不像 AI"）

盲测时每条只问一个二选一，问完再问一句为什么（可选）：

1. **愿意继续聊**：这两个回复，你更想接着跟哪个聊下去？
2. **阅读阻力**：哪个读起来更顺 / 更少需要回头再看一遍？
3. **刻意迎合感**：哪个更像在刻意学你说话？（这一条是反向分，**越像越差**）
4. **身份一致性**：给一段历史聊天记录 + 两条新回复，哪条更像同一个人说出来的？

第 3 条是专门为 `adapt` 设的陷阱探测：适配调不好就变成谄媚，而谄媚是"学词"不是"调结构"，用户能感觉到。

第 4 条对应 `profile` 的目标，是唯一能验证"像这个人"而不是"像人"的问题。

---

## 4. Judge：谁判（按我们真实的资源分级）

| 等级 | 做法 | 我们能不能用 |
|---|---|---|
| L0 自己无盲 | 自己看自己改的，觉得更自然 | **不能用**，这是闭环自证 |
| L0′ 自己盲测 | 打乱、不标来源，强制二选一 | **能用**，成本 20–25 分钟 |
| L1 模型判 | 让 GPT/Claude 打分 | 只做辅助，**不能当 ground truth**（AI 偏爱 AI） |
| L2 匿名真人盲测 | 2–3 个朋友，同一份卷子 | **可扩展**，但样本小、只能当旁证 |
| L3 真实场景行为 | QQ 上真聊 3 天，看主动多聊/中断率 | **最终裁判**，唯一不看指标的证据 |

本实验的实际执行：**L0′ 主判 + L2 旁证 + L3 终审**。

L0′ 的操作要求（不满足就作废）：
- 屏蔽来源：不能用"上面这条是改过的"这种顺序，用脚本随机化左右位置；
- 一次只看 40 组，中途不看指标、不看臂名；
- 每组 10 秒内选，超过 20 秒的直接跳过（犹豫本身就是信号，别硬选）；
- 填完之后才允许自己算指标。

---

## 5. 留出指标（Holdout）

`adapt` 的规则只会往这几个方向使劲：`chunk_len_p50`、`turn_chunks_median`、`hedge_per_kchar`、`end_punct_rate`、`chunk_len_cv`。

因此整簇留出、**有任何一条进过指令就作废**：

```
turn_share_3
turn_chunks_entropy
within_turn_cv_median
sentence_len_entropy
hedge_chunk_share
```

外加内容层：`echo_rate`（实验 05 的复读率）。

判据：C 臂在这 6 项上的 **|dev| 之和 ≤ A 臂的 70%**，才算"泛化到了没被优化的维度"。如果这 6 项变差而前 5 项变好，就是在过拟合指标——这是能抓到的最有价值的一种失败。

---

## 6. 预注册判据（四条，全写死）

n = 40 组盲测（从 120 条 prompt 里抽，seed 固定）。

| 编号 | 判据 | 阈值 | 含义 |
|---|---|---|---|
| **P1 人味** | C vs A 盲测胜率 | **≥ 65%**（≥26/40，二项检验 p<0.05） | 人确实觉得更好 |
| **P2 泛化** | C 在留出 6 项上 \|dev\| 之和 ÷ A 的同项之和 | **≤ 0.70** | 不是只修了被点名的地方 |
| **P3 非随机** | C 胜率 − D 胜率 | **≥ 15 个百分点** | 不是"加了随机性"的功劳 |
| **P4 相关性** | 每组 Δ(dev) 与 人选择 的 Spearman ρ | **≥ 0.30**（n=40） | 指标变化与人的感受同向 |

**A→D 若也能提高人评价**，则 P3 自动失败，同时 P1 的解释权作废——结论只能写成"提高来自随机性/多样性，与结构适配理论无关"。

**P1 失败但 P2 通过**：说明指标动了、人没感觉 → 这正是最危险的组合，结论写成"分布更像人 ≠ 人觉得更像人"，本身就是一个值得留档的负结果。

## 7. 执行顺序（每一步都能单独失败）

```
1. 生成 120 条 prompt                    （复用 04 的池，seed 固定）
2. 跑三臂 → data/val/{a,b,c}.jsonl       360 次调用，55 秒
   D 臂由 a.jsonl 本地扰动生成 → data/val/d.jsonl
3. 四臂分别 audit → 指标表 + holdout 表   （不掺人味，纯机器）
4. 抽 40 组，生成盲测卷（左右随机）        experiments/make_2afc.py
5. 自己盲测填卷（20–25 分钟，中途不看指标）
6. 算 P1–P4，写进本文件「结果」节
7. 若 P1 通过 → 上 QQ 真聊 3 天，看 L3 行为
```

## 8. 结果

### 8.1 机器侧（已跑，2026-11-28）

`python experiments/run_06.py --n 120 --workers 12` → `data/val/{a,b,c,d}.jsonl`、`summary.json`。

**C 臂拿到的两条指令**（`adapt.advise` 从本人 694 轮私聊里生成）：

```
这个用户习惯几乎不写句号（实测 end_punct_rate = 0.036），所以输出用这种形态：句末不用句号，句子可以断在半路。
这个用户习惯长短差得很开，有的三五个字，有的整段（实测 chunk_len_cv = 1.955），所以输出用这种形态：长短交错：不要每条都差不多长，允许一条只有两三个字。
```

| 指标 | A 原样 | B 禁词表 | C 适配 | D 随机扰动 |
|---|---|---|---|---|
| chunk_len_p50 | 64 | 57 | **16** | 43 |
| chunk_len_cv | 0.461 | 0.483 | 0.626 | 0.630 |
| end_punct_rate | 0.863 | 0.946 | **0.005** | 0.258 |
| hedge_per_kchar | 8.28 | 7.78 | 7.29 | 8.51 |
| hedge_chunk_share | 0.405 | 0.408 | 0.123 | 0.335 |
| turn_chunks_median | 1.0 | 1.0 | 1.0 | 1.0 |
| turn_share_3 | 0.033 | 0.008 | 0.108 | 0.017 |
| turn_chunks_entropy | 0.378 | 0.388 | 1.536 | 0.939 |
| within_turn_cv | 0.452 | 0.182 | 0.333 | 0.342 |
| sentence_len_entropy | 2.098 | 2.187 | 2.057 | 2.019 |
| **留出 5 项 \|dev\| 之和** | **45.61** | **47.99** | **12.10** | **37.82** |

**P2 泛化：12.10 / 45.61 = 0.27 ≤ 0.70 → 通过。**
（留出 5 项＝`turn_share_3`、`turn_chunks_entropy`、`within_turn_cv`、`sentence_len_entropy`、`hedge_chunk_share`；adapt 的规则没碰这几项。）

三条值得记的观察：

1. **C 的改善主要来自"长度"和"标点"，不是"条数"**。`turn_chunks_median` 四臂都是 1.0——模型根本没学会分条，C 只是把每一段改短了。所以"段数"这一簇的改善（entropy 0.38→1.54）其实是段被截短后自然变碎，不是它理解了"该分几条"。
2. **标点被过量执行**：C 的 `end_punct_rate` 0.005，落在人类带（0.0216–0.0504）之外的下侧，dev −2.15。用户的真实习惯是"很少写句号"（3.6%），不是"从不写"。措辞得改成"很少用句号"，否则就是另一个方向的过冲。
3. **对冲密度纹丝不动**（8.28 → 7.29）。`adapt` 只会照着"这个人偏离人群的方向"给指令，而这个人本来就在人类带内（hedge 1.25–1.75 带里），所以没规则触发；模型自身的对冲毛病（7–8 次/千字，人类 1.5）就没人管。→ **adapt 治的是"用户风格"，不治"模型毛病"，两者需要分开输出。**

### 8.2 人侧（L0′ 盲测，已跑）

填卷方式：直接在 `sheet.md` 里被选中的那段后面写 `Q1` / `Q2`（哪个问题选了它），
由 `experiments/score_6_marks.py` 解析回 `key.json` 的左右映射。
不想选的题留空即视为 pass，原因写在题末。

```bash
python experiments/score_6_marks.py data/val/marked.md --key data/val/key.json
```

**结果：40 组，36 组有效，4 组弃权（#11 #15 #29 #32）。**

| 问题 | C 胜 | 胜率 | 二项 p |
|---|---|---|---|
| q1 更想接着聊 | 32/36 | 88.9% | <1e-6 |
| q2 读着更顺 | 34/36 | 94.4% | <1e-6 |
| **q1+q2 合并** | **66/72** | **91.7%** | **7.3e-14** |

**P1（≥65%）：通过，且远超门槛。**
**P3（C−D ≥15pp）：本轮不可算**——盲测卷只放了 C vs A，D 臂没进卷。
**P4（Δdev 与人选择的相关）：本轮不可算**——需要逐条 dev 与逐条选择的配对，
下一轮把 40 组的逐条 dev 一起存下来才有。

q3（哪个更像在刻意学我说话）**全部未填**。这是有意的：一旦开始想"这句是不是在
学我"，q1/q2 的直觉判断就被污染了。代价是这轮没有"迎合度"的守卫，
只能靠弃权题的原因来侧面看。

**A 胜出的 5 组**：#1（q1）、#4（q2）、#6（q1）、#10（q1）、#19（q1 q2）。
共同点：都是**短句已经够用、长句多给了一点情绪**的场合——#6「嗯 就多了一根烤肠」
输给了「感觉整个套餐瞬间升级了似的」；#19 干脆认为 C 那句太冲、A 那句"被冤枉"的
委屈更接得住。也就是说：**短 ≠ 一定更好，短到把情绪削掉了就输**。

### 8.3 弃权题给出的两类新失败模式

1. **#11：两边都在认错**（"是我太着急了" / "是我先抢答了"）。判词：
   「ai味都很重，属于谄媚类型，而真人很少会真的在日常中认错，尤其是关系特别好的时候」。
   → C 臂只改了长度和标点，**没改"抢先认错"这个动作**。这是句式层之上的行为层，
   现在的 adapt 完全覆盖不到。
2. **#29 #32：关心与询问应当并存**。判词：「回答2是询问进度，回答一的后半段是关心」
   「询问和关心并存才好，因为他的人设是女性，如果是男的这种小事关心反而是显得关系远了」。
   → C 臂把长句削短时，**顺手把"关心"那半句削掉了**，只剩询问。说明"短"这个目标
   和"暖"这个目标会打架，形状卡需要一个"不许削掉的那半句"的例外条款。
3. **#15：C 和 A 几乎一样**（只差空格与标点）。说明当 C 的唯一改动是标点时，
   **人眼分辨不出来**——这类配对在卷子里等于送分给"没区别"，应当按"改动幅度"
   加权，或者干脆不放进盲测。

### 8.4 这次实验证明了什么、没证明什么

证明了：**结构指令能被人读出来**（91.7%，p=7e-14），而且不是靠点名的那几项
（留出项 45.61→12.10），所以不是"照指标改指标"的自证。

没证明：
- 判官是**被模仿者本人**，他知道自己在评"像不像我"，存在"我知道该选哪个"的先验；
  真正干净的下一关是**朋友盲测**（L2），以及 QQ 真聊（L3）。
- 只测了一个人、一个模型、一种池子、一个温度。
- "短就是好"这个混淆没有被排除——A 胜的 5 组恰好是"短到丢情绪"的场合，
  说明偏好不是单调的"越短越好"，但边界在哪没测出来。

## 9. 这份实验不能证明什么

- n=40，单个人（或加 2 个朋友）判 → 只能证明方向，不能证明普适；
- 只测 deepseek-flash 一个模型、temp=1.0；
- 盲测者知道自己在做实验（Hawthorne 效应）；
- 假设 D 臂的"随机"与真实随机同分布，但我们的随机是按基线分位抽的，本身带一点"像人"的倾向——所以 D 的胜率如果异常高，要回头检查这个偏置。
