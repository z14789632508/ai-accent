# 实验 02：真人基线的口径

基线不是"我觉得人这么说"，是**测量结果**。这份文档记录它怎么来的、测的是什么、哪里有偏。

## 语料来源

| 项 | 值 |
|---|---|
| 来源 | 本地 QQ 群聊记录（账号主人自有数据，经本人同意用于统计） |
| 规模 | 526,350 条带文字消息 · 77 个群 |
| 时间跨度 | 多年（群龄不等，最早的群有十年以上） |
| 群性质 | 游戏交流群、兴趣群、闲聊群为主（赛尔号/奥拉星类页游群占比最高） |
| 参与者 | 43 个说话人达到每群 ≥300 条的门槛，进入基线 |

**原文不进仓库。** `baselines/chat.json` 里只有每个指标的 p10/p50/p90，没有任何一句话。语料留在本地 `data/`（`.gitignore` 已排除）。

## 为什么按"说话人"算，不按群算

第一版基线是按群算的：每个群的所有消息混在一起测一份，再对群取中位数。听起来合理，实际是错的。

模型是**一张嘴**。拿几百个人的混合语料去和一张嘴比，等于把分布压平——几百人平均之后，band 会异常窄，中间那段谁都不像，稍微偏离就被判"异常"。

改成按说话人算之后：

- 每个 (群, 说话人) 组合、达到 ≥300 条门槛的，各自测一份；
- 再对**这些说话人之间**取 p10/p50/p90。

这样 band 描述的是"人这张嘴之间的差异范围"，和"这一个模型 vs 人"才是同一量级的问题。

## 口径细节

- **chunk** = 一条消息（发送出去的一次）。
- **turn** = 同一人在 **120 秒**内的连续多条。（微信群聊里"连发"是常态，单条分析会把节奏信息全丢掉。）
- **句末标点**：`。！？!?…~～.」』）)】` 与引号。QQ 里大量消息不以标点结尾，这是真人特征而不是噪声。
- **句子切分**：按 `。！？；…\n` 切，长度以字符计。`sentence_len_entropy` 用 10 字一档的分箱。

## 已知偏差（写出来，别假装没有）

1. **群聊 ≠ 私聊。** 群聊里有大量"草""笑死""1""？"这类一到三字的应答，会压低 `chunk_len_p50`、抬高短句占比。所以 `chunk_len_p50` 的 band（7–16）对私聊场景偏严——私家对话天然更长。**跨场景比这个数要小心。**
2. **语料偏游戏群。** 赛尔号、奥拉星这类群的语言习惯（黑话、复读、表情替代）不代表所有中文使用者。要更通用的基线，得补综合类群的语料。
3. **说话人门槛 300 条带来选择偏差。** 够 300 条的往往是群里最活跃的少数人，可能比沉默大多数更"话痨"、更爱连发。这个方向会把 band 往"更随意"推，也就是让模型更容易被判"太整齐"——所以本仓库的结论在这一侧偏保守，不算宽松。
4. **`sentence_len_entropy` 不可跨语料比。** 私聊口径下真实使用者是 2.50，群聊口径下只有 1.5–1.7（短消息把最短 bin 堆满）。这是分箱 + 语料口径的联合效应，不是"私聊更像人"。该指标因此标 experimental，报告必须同时印分箱宽度与语料来源。

## 复现

```bash
# 1) 用本地 jsonl（每行：{"ts":秒,"g":群号,"uid":发送者,"t":文本}）重建基线
python scripts/build_baseline_from_qq.py data/group_msgs.jsonl --min-msgs 300

# 2) 体检
aiaccent audit data/model_replies.jsonl --register chat --prescribe
```
